# 产品规范

## 使用范围

封闭式家庭阳台约 10～15 米，水源位于一端，有市电及现有水桶。`v0.1.0` 面向两盆植物的有人值守原型，支持独立监测、分区及分组供水。通过可信家庭局域网使用手机、平板或电脑浏览器，必要功能由 ESP32 自治。扩展至 7～12 盆依赖实际监测及供水通道、管路和保护能力。

## 模型与关系

以下为首版已批准的业务规范。M1-A 实现模型、校验与标定换算，M1-B 实现灌溉许可和执行规则，M1-C 通过模拟设备与存储运行应用服务。进度见[开发路线](ROADMAP.md)。

| 模型 | 职责与关系 |
| --- | --- |
| `Plant` | 保存名称、启停状态及可选的探头和分区引用。一盆植物各可绑定一个探头和一个分区，一个探头最多绑定一盆植物。 |
| `SoilSensor`、`PumpChannel` | 分别占用一个可用的采集或控制逻辑通道，同类通道唯一。每个实体独立保存标定，水泵还保存运行时限。 |
| `IrrigationZone` | 最小独立供水单元，独占一个水泵，可服务多盆植物。可选的代表性探头须绑定到本分区已启用的植物。 |
| `IrrigationGroup` | 至少包含两个分区的有序集合，成员必须存在且组内唯一。一个分区可加入多个组。 |
| `IrrigationRule` | 每个分区持有自己的规则，保存自动模式、单次与每日额度、每日定时剂量、智能阈值与连续次数、智能剂量及冷却时间。 |
| `SensorReading` | 保存带采样时间和有效状态的土壤或空气读数。 |
| `IrrigationRecord` | 记录分区、水泵、请求来源、目标剂量、采用的标定流量、运行时长、估算水量及必要的时间和结果。无法确认的运行时长和估算水量保留为空。 |
| `SystemConfig` | 管理业务配置和全局参数，包含 `schemaVersion`。实时读数、执行状态和历史由各自的运行模块管理。 |

- 各实体类型分别使用唯一的非零 32 位数值 ID。业务 ID 与逻辑通道、物理连接独立，修改名称或绑定时保持 ID。配置应用服务须保存 ID 分配状态，防止删除后复用。关系以引用方为准，优先支持停用，解除引用后显式删除。
- 结构校验检查实体、通道、引用、版本与已填写参数。允许未绑定、未标定和参数待填写的准备状态。手动静态就绪需要水泵流量标定、完整运行时限及分区额度。定时还需完整且满足剂量和时长限制的定时项。智能还需规则参数、同分区有效植物的已标定代表性探头和可执行的固定剂量。静态就绪供后续用例校验模式和实际请求。
- 空分区可作为配置准备状态。正常手动、定时和智能灌溉均要求分区内至少有一盆启用植物。停用单盆只改变业务状态，共用水路仍按分区供水。空分区的水泵测试由后续独立的有人值守设备调试模式处理。
- 两盆原型分别绑定探头 1、2 和分区 1、2，各分区使用同序号的水泵通道。物理连接见 [Rev B 硬件基线](../hardware/rev-b/README.md)。系统容量取决于可用硬件通道。

## 灌溉规则

- 手动、定时和智能请求使用 [同一执行入口](ARCHITECTURE.md#灌溉执行)。剂量以分区供水总量为准，分区内各盆实际水量无法由该剂量推算。超过单次或每日额度、最长运行时限的请求直接拒绝，按固定剂量换算运行时长，无实时湿度反馈停泵。正常按量执行要求有效日期时间和可靠的关键状态持久化，同一时间只允许一路水泵运行。
- 自动模式为关闭、定时或智能，默认关闭。定时配置支持每日多个互异时刻，每项有明确剂量。智能模式默认连续三次有效、低于阈值的新采样触发。同次采样只计一次，缺测、无效、过期或达到阈值会中断计数。任意来源的灌溉结束后均进入该分区的智能冷却期，期间不累积计数，结束后重新采集。手动和定时请求仍受统一执行保护，可在智能冷却期间受理。
- 全部分区的定时和智能灌溉共用一个可配置的本地时段。开始分钟为 0～1439，结束分钟为 1～1440，1440 表示 24:00。开始必须早于结束，区间含开始、不含结束，首版使用单个当日时段。关闭限制时自动灌溉全天可申请，仍须通过原有跨日及安全检查。自动执行在受理和发出启动许可前都须预计能在时段结束前完成。手动、手动分组、全天采集、历史写入、网页读取和安全停泵各自遵循原有条件。
- 首版分组以手动顺序执行为主，明确每个成员的剂量。组开始前预查全部成员并检查累计计划时长，预计触及午夜就整体拒绝。各成员启动前再次校验，失败或额度日期变更即取消剩余成员，已执行成员按原额度日结算。普通手动请求遇忙不抢占。自动任务冲突采用有限容量、稳定顺序和重新校验。自动规则配置在分区。
- 启泵前一致地持久化执行凭据并保守预留分区每日额度，三种来源均计入。确认未启动时可释放预留，确认运行时间时按标定流量估算并向上取整结算，结果未知时保留全部预留。安全额度以关键状态为依据，保存失败时拒绝新的正常请求。
- 上电默认停泵，非阻塞运行，设置独立停止时限、看门狗与故障处理。全局停止优先结束当前灌溉、取消待执行任务，并独立持久化自动暂停状态，等待用户主动恢复。软件保护须与后续硬件保护一同验收。
- 重启不续灌，也不恢复未完成的分组或待执行任务。异常中断且执行量未知时保守记账，待人工确认并解除保护。正常重启在配置、时间及关键状态有效且无保护锁定时可恢复原自动模式，并保留自动暂停。重启后重新建立单调时间，无法确认冷却余量时保守等待。

额度使用已结算累计量和唯一未结算预留。每日额度是当日上限，剩余量到期失效。符合日期推进条件后按配置上限和零已用量开启新额度日，剩余量不累计、不结转，也不触发补灌。降低每日限额保留累计值，超过新限额时可用量为零。确认用量超过预留时据实保守记账并锁定故障，整数溢出时饱和锁定。结算保存失败期间继续占用全局执行资源，并以此前可靠保存的预留凭据作为掉电恢复依据。分区使用稳定 ID 记账。当日已留有凭据的分区与逻辑泵通道须保持关联，配置应用需保护删除、重建及通道重新绑定时的额度和冷却一致性。

任意来源确认发生灌溉或发生未知中断时保存最近灌溉信息，即使当时尚未配置智能冷却。重启后，对留有灌溉信息的分区按当前配置重新等待完整冷却。智能候选需要最新读数仍低于阈值且保持有效。两次有效采样的间隔超过采集周期加容差时重计，容差取周期的 10%（按毫秒向下取整）与 30 秒中的较小值。时段外继续监测，暂停智能触发计数。重新进入允许时段后用新采样开始计数。变更时段后重新建立自动触发依据，额度、定时消费凭据和冷却信息继续保留。触发机会在被尝试后消费，随后依靠新的连续低湿度采样触发。

手动和分组请求按稳定请求 ID 与明确的剂量内容去重。凭据容量为八条，已满且无可靠清理结果时拒绝新请求。每条凭据至少保留至请求可靠结束后十分钟，未结束的执行及分组持续保留。当前启动周期使用单调时间。重启后，以可靠加载的结束凭据为依据，重新等待至少十分钟，并在有已保存 UTC 依据时复核可信时钟及期限。时钟异常时保守保留。期限为技术默认值，客户端须在有效重试期内提交原 ID 和内容。

全局人工停止可以取消等待保存及等待启动的执行，并保持自动暂停。停泵确认、恢复自动灌溉及解除故障锁定各自独立。解除故障前须确认水泵关闭且关键状态已可靠结算，恢复自动时重新建立触发依据。

停泵证据使用设备侧单调时刻。确认未启动时运行时长应为空或为零。已测量时须提供实际停止时刻和正运行时长，有可信启动时刻时两者的差值须与报告一致。未收到启动时刻时，许可到实际停止的间隔为运行时长上界。未知用量只提供确认关闭时刻，时长留空。证据矛盾时按未知用量锁定并保留全额预留，已确认的实际启停时刻能证明超量时计入超额，超出时长或额度表示范围时饱和记账。

探头端点、泵流量、泵运行时限、剂量、额度、智能阈值和冷却时长由配置与标定提供。设备实际投入使用前须完成硬件验收。

## 采集与标定

- 土壤相对湿度指数采用每个探头独立的干湿两点标定，公式为 `(raw - dryRaw) / (wetRaw - dryRaw) × 100`，兼容正向和反向响应，要求端点不同。显示限制在 0～100%，保留原始读数及超范围状态。指数与体积含水率、质量含水率和田间持水量百分比采用不同口径。实际标定方法、ADC 有效量程和可用的端点差值在设备与实物阶段验证。
- 读数区分缺测、采集失败、无效、未标定、超范围、过期和有效。只有有效的新采样可用于智能触发。保留原始采样时间，读取缓存不得刷新采样时间。日期时间缺失时可保留单调采样时间。
- 空气 VPD 采用 `es = 0.6108 × exp(17.27 × T / (T + 237.3))`，`VPD = es × (1 - RH / 100)`。监测计算接受有限的 −40～60 °C 及 0～100% RH，范围用于限制家庭环境公式外推，设备量程由后续驱动验证。RH 为 100% 时 VPD 为零。VPD 仅用于监测。[FAO-56 第 3 章](https://www.fao.org/4/X0490E/x0490e07.htm)
- 各路分别标定水泵，流量为 `实际收集量(mL) / 标定时长(ms) × 60000`，目标时长为 `目标水量(mL) / 标定流量(mL/min) × 60000`。安装后按实际管路、扬程和出水条件重新标定。目标时长先比较未取整值与最长时限，然后向下取整至毫秒，结果为零或低于已配置的最短有效时长则拒绝。
- 估算水量为 `标定流量(mL/min) × 确认的运行时长(ms) / 60000`。只有确认未运行时才记录零时长，运行时长未知则水量估算也未知。当前水量来自流量标定与时间估算，实时出水量需要流量传感器实测。

| 数据 | 内部口径 |
| --- | --- |
| ADC 原始读数 | 有符号 32 位 ADC count |
| 土壤相对湿度、空气相对湿度、空气温度、VPD | 浮点 %、%、°C、kPa |
| 目标剂量、单次及每日额度 | 无符号 32 位整数 mL |
| 水泵标定流量、估算水量 | 浮点 mL/min、mL |
| 运行时长、单调时间、UTC 时间戳 | 无符号 32 位 ms、无符号 64 位 ms、有符号 64 位 s |
| 定时时刻、固定时区偏移 | 本地当日分钟 0～1439、有符号分钟（绝对值小于 24 小时） |

## 时间与历史

运行时长、冷却、超时和数据新鲜度使用单调时间。定时、历史及每日额度使用 UTC 时间戳和可配置的固定时区偏移，首版无夏令时切换。NTP 校时有效且设备持续供电时，断网可沿用内部时钟。无有效时间时禁止正常灌溉，仅允许后续独立的有人值守限时设备调试模式。

定时执行按分区 ID、本地日期、定时时刻及执行凭据去重，错过的时刻不补灌。时钟回拨或时区变更不得重复获得额度或触发任务。首版拒绝预计跨越本地自然日边界的请求，运行中校时或异常跨日时保守记账。

Core 使用调用方提供的可信 UTC 及单调时间。后续日期推进需有至少 60 秒一致的时钟观察、原时区与当前时区均越过保留额度日，并确认旧日关键状态已经保存且执行资源空闲。跨日回拨暂停正常灌溉，保留已保存额度。时区变更暂停当前额度日的定时灌溉，恢复偏移亦继续保留该日保护。跨日预检查按秒级 UTC 的最坏小数秒保守比较，原执行始终按预留日期结算。

定时轮询观察连续推进进入目标分钟后，按分区 ID 升序产生候选。定时项可以配置在允许时段外，到期时消费并跳过。每次最多保留每分区一个自动候选，总容量为 16。候选须在目标分钟内重新验证并获准启动。首次时间同步、时钟跳变以及从暂停恢复时跳过已错过的窗口。定时消费水位记录当日已处理到的分钟，剂量修改或重新添加同一分钟均沿用已有消费记录。水泵停止判断和定时轮询各自独立于采集周期。

| 参数 | 默认值 |
| --- | --- |
| 传感器采集 | 全天，每 5 分钟一次 |
| 数据有效期 | 两个采集周期（默认 10 分钟） |
| 自动灌溉允许时段 | 启用，本地 05:00 至 23:00 |
| 固定时区 | UTC+08:00 |
| 仪表盘刷新 | 5 秒 |
| 历史采样写入 | 5 分钟 |
| 监测历史保留 | 14 天 |
| 灌溉历史保留 | 90 天，受容量约束 |
| 历史格式及清理 | 按日追加 CSV，删除过期完整日文件 |
| 维护空间 | 约 20%，后续按实测文件评估 |

历史写入失败时提示故障并保留文件系统。配置持久化详见 [存储职责](ARCHITECTURE.md#存储与发布)。

## 访问与首版范围

首版单管理员，使用基本访问密码。控制和配置需要认证，实施必要的跨站请求保护、参数校验和请求大小限制。设备以 STA 接入家庭网络，必要时使用带密码的临时 AP 配网，完成后关闭 AP。延期项目见 [开发路线](ROADMAP.md)。

## UI 设计基线

PlantHub 中文名为家庭智慧灌溉系统。界面采用绿色圆角方形和白色幼苗标志，主色为低饱和度自然绿，背景为白色及浅灰色。使用简体中文、轻量卡片和手机优先的响应式布局，兼顾平板与电脑。绿色表示正常，橙色提示警告，红色表示异常和危险操作。

### 首版五个页面

| 页面 | 内容 |
| --- | --- |
| 首页仪表盘 | 空气温度、空气相对湿度、VPD、植物湿度卡片、设备运行状态、快捷灌溉及今日灌溉统计 |
| 植物管理 | 新增、编辑及停用植物，绑定探头、关联分区、独立湿度标定 |
